# DSH × WPS

把 AI 助手嵌进 WPS，**用你自己的 API Key**、直连你选的模型厂商。

不是一个套壳聊天框：目标是让助手真的能读写你的文档 —— 但改动**默认以修订形式出现**，
并且它的一整轮操作会打包成**一次撤销**，按一下 `Ctrl+Z` 就能全部退回。

> **当前状态：阶段 1（骨架可用）。**
> 填充 API Key、多厂商、测试连接、基础对话已经能用；
> **文档读写（修订留痕、整轮撤销）还没接上**，属于阶段 3。
> 详细进度见 [阶段说明](#阶段与进度)。

> **验证状态（请知悉）：**
> 本地服务已通过 18 项接口自测 + 19 项页面静态校验，并已对真实厂商（DeepSeek）
> 跑通错误链路。但**加载项前端尚未在真实 WPS 里加载验证过** ——
> 构建环境无法写入 WPS 的注册目录。
> 你双击 `install.cmd` 后如果「AI 助手」标签页没出现，请看下面的排查章节。

```

WPS 窗口
┌────────────────────────────────────────────┐
```

## 安装

**接收者不需要装任何东西。** 双击 `install.cmd` 就行 —— 它会自己把 Node 运行时下下来。

1. 双击 **`install.cmd`**
2. **完全退出 WPS**（关掉所有窗口，确认托盘里也没有残留进程），然后重新打开
3. 顶部会多出「AI 助手」标签页 → 点「打开助手」→ 首次使用会自动弹出模型设置

安装脚本做四件事：

| 步骤 | 说明 |
|---|---|
| 1. 准备 Node 运行时 | 优先用系统已装的；**没有就自动下载便携版**（约 35 MB，只下一次，解到 `%APPDATA%\dsh-wps\runtime\`） |
| 2. 注册加载项 | 在 WPS 的加载项目录写 `publish.xml`，注册文字/表格/演示三个组件。**会先备份原有文件**，且不覆盖别人的条目 |
| 3. 注册开机自启 | 让本地服务常驻（加载项自己拉不起进程 —— WPS 有沙箱） |
| 4. 启动服务 | 立刻可用 |

> ⚠️ **关掉 WPS 窗口 ≠ 重启 WPS。**
> `publish.xml` 只在 WPS **进程启动**时读取。只要有后台进程残留，新开的窗口会附着上去、
> 不会重新读配置，加载项就不会出现。这一步是实测踩过的坑，务必确认进程真的退干净了。

### 分享给别人

```bash

```

这个脚本会**扫描密钥**，扫到就拒绝出包 —— 见下面「打包前的安全检查」。

## 使用

打开侧栏后，在「模型设置」里选厂商、粘贴 Key、点「测试连接」，
通了就保存。然后选中一段文字，在侧栏里提问即可 —— **助手会直接改在文档里**。

侧栏左下角有个**「引用当前选区」**开关（默认开）。
勾上时，你选中的文字会随问题一起发给模型，省一轮工具调用。

## 助手能直接改文档

选中一段文字说「帮我润色」，助手会**直接改在文档里** ——
不是在聊天框里给你一段文字让你自己复制粘贴。

### 它能调用这些工具

| 工具 | 作用 |
|---|---|
| `get_document_info` | 读文档信息（文件名、选中多少字、总字数、修订开关状态） |
| `get_selection` | 读你当前选中的文字 |
| `get_document_text` | 通读正文（长文档会截断并说明） |
| `replace_selection` | 用新文字替换选中内容 |
| `replace_all` | 全文查找替换 |
| `insert_text` | 在光标处插入文字 |

模型自己决定调哪个。你不需要说"请调用 replace_selection"，说人话就行。

### 两道安全兜底（默认都开着）

**① 修订留痕。** 助手的每个改动都以**修订**形式出现，你可以逐条接受或拒绝 ——
它不会悄悄改掉你的文档。

**② 整轮撤销。** 助手一轮里的所有改动会打包成**一个**撤销单元，
按一下 `Ctrl+Z` 全部退回，而不是狂按几十次。

实现上用的是 `Application.UndoRecord.StartCustomRecord` / `EndCustomRecord`
（阶段 0 已实测验证），而且**只在真正要写文档时才开启** —— 纯提问不会污染你的撤销栈。

想不走留痕、直接改，可以在模型设置里切换「写入方式」。

### 它是怎么做到的（一条反向通道）

文档操作**只能在 WPS 加载项上下文里执行**（只有它持有 `window.Application`），
而 agent 循环跑在本地服务里。所以多了一条反向通道：

```
侧栏 ──POST /api/chat──▶ 本地服务（agent 循环）
                            │  ▲
        SSE: tool 事件 ─────┘  └──── POST /api/tool-result
                            ▼         （工具执行结果）
                      侧栏：用 JSAPI 改文档
```

服务把「模型要求调工具」经 SSE 推给侧栏，侧栏执行完把结果 POST 回来，循环继续。
多步任务（先读选区、再改写，再检查）就是这样一轮轮转下去的。

### 几个例子

- 「帮我润色一下选中的这段」→ 直接改在文档里，走修订
- 「把全文的『用户』都改成『客户』」→ `replace_all`，会告诉你改了几处
- 「这段逻辑有什么问题？」→ 只读，不动文档
- 「在这后面续写一段」→ `insert_text`

改完不满意？按一次 `Ctrl+Z` 整轮退回。

| 厂商 | 说明 |
|---|---|

| **智谱 GLM** | `glm-4-flash` 有免费额度 |

| **Anthropic** | 独立协议，本项目已单独适配 |

### 换成你自己喜欢的模型

三条路，随便挑：

1. **点「拉取列表」** —— 直接向厂商要一份**真实可用**的模型清单，
   拿到后点模型输入框就能从下拉里挑。不用记名字，也不用等这里更新。
2. **从预设候选里选** —— 每个厂商带几个常见模型，切换厂商会自动填。
3. **直接手打** —— 模型名是可编辑输入框，不是只读下拉框。
   厂商刚出的模型、或者预设没覆盖到的，直接敲进去就行。

> 拉取走的是标准的 `GET /models`（OpenAI 兼容网关和 Anthropic 都支持）。
> 少数网关没实现这个接口 —— 那种情况会提示你，手填模型名即可，不影响使用。

## 工作原理

```
WPS 加载项（CEF / Chromium 104）
   ├─ 聊天侧栏         ← CreateTaskPane
   │    └─ 文档操作     ← js/doc.js，唯一持有 window.Application 的地方
   └─ 配置悬浮窗       ← ShowDialog(..., false)
              │
              │  HTTP（配置）+ SSE（对话下行）+ POST（工具结果上行）
              │  + BroadcastChannel（各页面之间）
              ▼
   本地服务（Node，零第三方依赖，默认 127.0.0.1:43130）
   ├─ 托管加载项静态文件
   ├─ 配置与凭据读写
   ├─ agent 循环：模型 ↔ 工具，最多 6 步          ← server/agent/
   │    └─ 运行时是可替换接口，以后接 DSH 只换实现
   └─ 模型适配：OpenAI 兼容 + Anthropic（含 function calling 流式）
              │
              ▼
        你选的模型厂商
```

### 三个关键设计决定

**① 请求由本地服务发出，不由加载项页面直接发。**
页面直连厂商 API 会撞 CORS（各家政策不同），Key 也会落在浏览器上下文里。
走本地服务两个问题都不存在。

**② 加载项由本地服务托管，所以是同源。**
加载项页面的 `location.origin` 就是服务地址 —— 不需要端口发现，也不需要配 CORS。

**③ 本地服务必须由外部启动。**
WPS 对加载项做了进程/COM 沙箱，实测 `CoCreateInstance('WScript.Shell')` 会报
`can not create`，加载项**无法**拉起外部进程。所以 `install.cmd` 会注册开机自启。

## 数据放在哪

| 内容 | 位置 |
|---|---|
| 非敏感配置 | `%APPDATA%\dsh-wps\config.json` |
| **API Key** | `%APPDATA%\dsh-wps\credentials.json` |
| 加载项注册 | `%APPDATA%\kingsoft\wps\jsaddons\publish.xml` |

Key 也可以走环境变量，优先级更高：`DEEPSEEK_API_KEY`、`OPENAI_API_KEY` ……（厂商 ID 大写 + `_API_KEY`）。

### ⚠️ 关于「每次都要重新输入 API」

**配置目录由启动服务时的 `DSH_WPS_HOME` 决定，默认是 `%APPDATA%\dsh-wps`。**

如果换了一个 `DSH_WPS_HOME` 去启动服务（这在跑测试时很常见），
服务读的就是**另一个目录**，你之前填的 Key 自然"不见了" ——
于是你会以为 Key 没保存，重新填一遍。

所以：

- **日常使用**：用 `install.cmd` 或 `start-service.cmd` 启动，别设 `DSH_WPS_HOME`
- **跑测试**：才用独立的目录和端口（见上面「跑测试前必须起一个专用测试实例」）
- 服务启动时会把它实际使用的配置目录**打印出来**，对不上就是这里的问题

另外，设置窗口里的 Key 输入框**永远是空的**（保存后就不再回传前端，这是安全设计）。
如果已经存过，输入框里会显示 `••••••••（已保存，留空即不修改）`，**不需要重填**。

### ⚠️ 别把凭据提交进仓库

`credentials.json` 里是你的真实 Key。这个项目是要分享出去的 ——
已经在 `.gitignore` 里屏蔽了 `credentials.json` / `*.key` / `.env` / `dev/testhome*`，
但**打包成 zip 发给别人时要额外确认一遍**。

### 打包前的安全检查

`dev/build-release.mjs` 不是简单的压缩，它把"别把 Key 发出去"做成了**强制流程**：

```
[1/4] 扫描源目录里的密钥…
[2/4] 复制文件…
[3/4] 复扫成品…          ← 复制之后再扫一遍，防止有东西在搬运途中被带进来
[4/4] 打包…
```

扫到就**直接失败、不出包**。检查项：

| 特征 | 说明 |
|---|---|
| `sk-` 开头的长串 | OpenAI / DeepSeek / Moonshot 等主流厂商的 Key 格式 |
| `Bearer <长串>` | 写死在代码里的 token |
| `apiKey` 后面的长赋值 | 硬编码的凭据 |
| `-----BEGIN ... PRIVATE KEY-----` | 私钥块 |
| `C:\Users\<用户名>\AppData` | 本机用户名路径（顺带防止泄漏环境信息） |

明显是占位符的值（含 `fake` / `dummy` / `fixture` / `not-a-credential` 之类）会跳过 ——
否则测试文件里的假 Key 会让扫描变成"狼来了"，久而久之就没人看了。

排除的目录：`node_modules/`、`dist/`、`.git/`、`runtime/`、`testhome*/`。

### ⚠️ 跑测试前必须起一个**专用测试实例**

测试脚本会**写配置和假 Key**。如果跑在你自己那个实例上（默认 43130），
它会**覆盖掉你填的真实 API Key**，并且真的拿你的 Key 去发请求（花你的钱）。

```cmd
:: 另开一个窗口，用独立的配置目录和端口

set DSH_WPS_PORT=43131
node server\index.mjs
```

然后测试默认就会打 43131：

```bash
node dev/selftest.mjs            # 接口自测（18 项）
node dev/check-pages.mjs         # 页面静态校验（22 项）
node dev/page-sim.mjs            # 页面运行时模拟（21 项）

# 工具调用链端到端测试 —— 需要模拟模型一起跑
node dev/mock-llm.mjs            # 另开一个窗口（默认 43199）
node dev/tool-loop-test.mjs      # 验证"助手真的改了文档"（13 项）
node dev/models-test.mjs         # 模型列表拉取（3 条路径）
```

想把测试指到别处：`set DSH_WPS_TEST_URL=http://127.0.0.1:xxxx`。

### 四层自测的分工

| 脚本 | 验证什么 | 抓不到什么 |
|---|---|---|
| `selftest.mjs` | 接口、静态托管、配置读写、错误翻译 | 前端 |
| `check-pages.mjs` | 内联脚本语法、元素 id 交叉校验、**ribbon 属性冲突**、回调实现度 | 运行时的空引用、逻辑错误 |
| `page-sim.mjs` | **真正执行页面脚本**（极简 DOM + 真实后端），并模拟点击 | 工具调用链、CEF 特有渲染问题 |
| `tool-loop-test.mjs` | **整条工具调用链**：模拟模型 → agent 循环 → 侧栏执行 → 文档真的被改 | 真实 WPS 的 JSAPI 行为差异 |

`tool-loop-test.mjs` 是含金量最高的一个：它断言的是**文档对象真的被改了**、
**撤销记录真的开了又关**，而不是"函数被调用了"。而且不需要真 Key、不花钱。

### 有用的环境变量

| 变量 | 作用 |
|---|---|
| `DSH_WPS_PORT` | 换端口（默认 43130）。改完要重跑 `install.cmd` |
| `DSH_WPS_HOME` | 换配置目录（默认 `%APPDATA%\dsh-wps`）。跑测试时很有用，别污染真实配置 |
| `DSH_WPS_LOG` | 把日志同时写一份到文件。隐藏窗口启动时排查全靠它 |
| `<厂商ID>_API_KEY` | 用环境变量提供 Key，优先级高于配置文件，不落盘 |

### 日志里的 `[WPS]` 标记

静态请求的日志会带 UA 标记：`[WPS]` 表示来自 WPS 内嵌浏览器，
`[非WPS]` 表示来自脚本或 curl。排查"加载项到底有没有在 WPS 里跑起来"时一眼就能分清。

改前端不用重启服务（静态文件不缓存）；改完在 WPS 里重开面板即可。
改服务端需要重启 `node`。

**调试技巧**：WPS 里打不开 DevTools，所以前端做了**错误上报** ——
任何 JS 报错都会 POST 到 `/api/clientlog` 并打在服务端控制台上。
页面"点了没反应"时，先看服务端窗口。

### 换端口

```cmd
set DSH_WPS_PORT=43131
node server\index.mjs
```
换端口后记得重跑 `install.cmd`（它会把新地址写进 `publish.xml`）。

## 排查

**先看日志。** 服务如果是通过安装脚本（隐藏窗口）启动的，日志在：

```
%APPDATA%\dsh-wps\service.log
```

里面能直接看到：加载项有没有来取文件（`[WPS]` 标记）、有没有前端报错、模型请求成没成。

**WPS 里没有「AI 助手」标签页**

1. **确认进程真的退干净了**。这是最常见的原因：关窗口不算重启。
   任务管理器里结束所有 `wps.exe` / `et.exe` / `wpp.exe`，再打开。
2. 确认 `%APPDATA%\kingsoft\wps\jsaddons\publish.xml` 存在，且里面 `url` 指向
   `http://127.0.0.1:43130/`（端口改过的话就是你改的那个）。
3. 确认服务在跑：浏览器打开 <http://127.0.0.1:43130/api/ping> 应该看到 JSON。
   没反应就跑 `start-service.cmd`，看它报什么错。

**侧栏显示「本地服务没有运行」**

服务没起来。双击 `start-service.cmd`，把那个黑窗口留着别关。
如果它说端口被占用，说明服务其实已经在跑了 —— 检查上面第 3 步。

**点了「发送」没反应 / 面板空白**

在服务端的窗口里找 `前端报错 [...]` 开头的行。所有前端 JS 报错都会回传到那里，
因为 WPS 里打不开 DevTools。

**连接测试报 401 / 404 / 超时**

| 提示 | 多半是 |
|---|---|
| API Key 无效或已过期 | Key 复制错了，注意首尾别带空格换行 |
| baseURL 或模型名不对 | 地址要填到 `/v1` 为止；模型名照厂商文档核对 |
| 连接超时 | 网络不通，或该厂商在国内需要代理 |
| 连接被拒绝 | 用 Ollama 的话，确认 Ollama 本身已经启动 |

**想彻底重来**

```cmd
uninstall.cmd                 # 移除加载项和自启，保留配置
uninstall.cmd -PurgeConfig    # 连配置和 API Key 一起删掉
```
