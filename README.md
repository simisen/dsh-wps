# DSH × WPS

把 AI 助手嵌进 WPS，**用你自己的 API Key**、直连你选的模型厂商。

不是一个套壳聊天框：目标是让助手真的能读写你的文档 —— 但改动**默认以修订形式出现**，
并且它的一整轮操作会打包成**一次撤销**，按一下 `Ctrl+Z` 就能全部退回。

## 它长什么样

```
                 ┌─────────────────────────┐
                 │  ⚙ 模型设置（悬浮框）     │  ← 填完可关，随时从 Ribbon 或齿轮重开
                 │  厂商  [DeepSeek      ▾] │

                 │  [ 测试连接 ]  [ 保存 ]   │
                 └─────────────────────────┘
WPS 窗口
┌────────────────────────────────────────────┐
│ Ribbon:  [AI 助手]  [模型设置]              │
├──────────────────────────┬─────────────────┤
│                          │  聊天侧栏（停靠） │
│       文档编辑区          │  ┌───────────┐  │

│                          │  ├───────────┤  │

│                          │  └───────────┘  │
└──────────────────────────┴─────────────────┘
```

- **聊天**用停靠侧栏：高频使用，不遮挡文档
- **配置**用悬浮窗：低频使用，填完关掉，随时重开
- 两者通过 `BroadcastChannel` 联动，保存设置后侧栏立刻刷新

## 安装

**接收者不需要装任何东西。** 双击 `点我启动助手.cmd` 就行 —— 它会自己把 Node 运行时下下来。

1. 双击 **`点我启动助手.cmd`**
2. **完全退出 WPS**（关掉所有窗口，确认托盘里也没有残留进程），然后重新打开
3. 顶部会多出「AI 助手」标签页 → 点「打开助手」→ 首次使用会自动弹出模型设置

> 不想看这份文档的人，直接把 zip 丢给他 —— 压缩包里有一份
> **`使用说明.txt`**，**完全不懂电脑的人照着做也能装完**：
> 每一步都是「双击哪个文件、看到什么才算成功、失败先看哪一条」。
> 面向用户的三个脚本也都改成了中文名：`点我启动助手` / `点我卸载助手` / `点我修复助手`。

安装脚本做四件事：

| 步骤 | 说明 |
|---|---|
| 1. 准备 Node 运行时 | 优先用系统已装的；**没有就自动下载便携版**（约 35 MB，只下一次，解到 `%APPDATA%\dsh-wps\runtime\`） |
| 2. 注册加载项 | 在 WPS 的加载项目录写 `publish.xml`，注册文字/表格/演示三个组件。**会先备份原有文件**，且不覆盖别人的条目 |
| 3. 注册开机自启 | 让本地服务常驻（加载项自己拉不起进程 —— WPS 有沙箱） |
| 4. 启动服务 | 立刻可用 |

> ⚠️ **关掉 WPS 窗口 ≠ 重启 WPS。**
> `publish.xml` 只在 WPS **进程启动**时读取。只要有后台进程残留，新开的窗口会附着上去、
> 不会重新读配置，加载项就不会出现。这一步是实测踩过的坑，务必确认进程真的退干净了。

### 分享给别人

```bash
node dev/build-release.mjs      # 产出 dist/dsh-wps-<版本>.zip
```

这个脚本会**扫描密钥**（扫到就拒绝出包）并**校验 zip 里中文文件名的 UTF-8 标志位**

见下面「打包前的安全检查」和「Windows 中文编码」。
接收者拿到 zip 后：解压 → 双击 `点我启动助手.cmd` → 完事。

## 使用

打开侧栏后，在「模型设置」里选厂商、粘贴 Key、点「测试连接」，
通了就保存。然后选中一段文字，在侧栏里提问即可 —— **助手会直接改在文档里**。

侧栏左下角有个**「引用当前选区」**开关（默认开）。
勾上时，你选中的文字会随问题一起发给模型，省一轮工具调用。

## 助手能直接改文档

选中一段文字说「帮我润色」，助手会**直接改在文档里** ——
不是在聊天框里给你一段文字让你自己复制粘贴。

### 它能调用这些工具

| 工具 | 作用 |
|---|---|
| `get_document_info` | 读文档信息（文件名、选中多少字、总字数、修订开关状态） |
| `get_selection` | 读你当前选中的文字 |
| `get_document_text` | 通读正文（长文档会截断并说明） |
| `replace_selection` | 用新文字替换选中内容 |
| `replace_all` | 全文查找替换 |
| `insert_text` | 在光标处插入文字 |

模型自己决定调哪个。你不需要说"请调用 replace_selection"，说人话就行。

### 两道安全兜底（默认都开着）

**① 修订留痕。** 助手的每个改动都以**修订**形式出现，你可以逐条接受或拒绝 ——
它不会悄悄改掉你的文档。

**② 整轮撤销。** 助手一轮里的所有改动会打包成**一个**撤销单元，
按一下 `Ctrl+Z` 全部退回，而不是狂按几十次。

实现上用的是 `Application.UndoRecord.StartCustomRecord` / `EndCustomRecord`
（阶段 0 已实测验证），而且**只在真正要写文档时才开启** —— 纯提问不会污染你的撤销栈。

想不走留痕、直接改，可以在模型设置里切换「写入方式」。

### 它是怎么做到的（一条反向通道）

文档操作**只能在 WPS 加载项上下文里执行**（只有它持有 `window.Application`），
而 agent 循环跑在本地服务里。所以多了一条反向通道：

```
侧栏 ──POST /api/chat──▶ 本地服务（agent 循环）
                            │  ▲
        SSE: tool 事件 ─────┘  └──── POST /api/tool-result
                            ▼         （工具执行结果）
                      侧栏：用 JSAPI 改文档
```

服务把「模型要求调工具」经 SSE 推给侧栏，侧栏执行完把结果 POST 回来，循环继续。
多步任务（先读选区、再改写，再检查）就是这样一轮轮转下去的。

### 几个例子

- 「帮我润色一下选中的这段」→ 直接改在文档里，走修订
- 「把全文的『用户』都改成『客户』」→ `replace_all`，会告诉你改了几处
- 「这段逻辑有什么问题？」→ 只读，不动文档
- 「在这后面续写一段」→ `insert_text`

改完不满意？按一次 `Ctrl+Z` 整轮退回。

## 支持的厂商

内置 9 个预设，选中就把接口地址和候选模型填好，你只需要粘贴 Key：

| 厂商 | 说明 |
|---|---|
| **DeepSeek** | 官方直连。工作日 18:00–次日 9:00 与周末全天是谷时价 |
| **Kimi / Moonshot** | 长文本见长 |
| **智谱 GLM** | `glm-4-flash` 有免费额度 |
| **通义 / DashScope** | 阿里百炼的「兼容模式」端点 |
| **硅基流动** | 聚合平台，一个 Key 调很多开源模型 |
| **OpenAI** | 国内访问通常需要代理 |
| **Anthropic** | 独立协议，本项目已单独适配 |
| **Ollama 本地** | 不用 Key、不花钱，但吃显卡和内存 |
| **自定义** | 任何 OpenAI 兼容网关，把 baseURL 填到 `/v1` 为止 |

### 换成你自己喜欢的模型

三条路，随便挑：

1. **点「拉取列表」** —— 直接向厂商要一份**真实可用**的模型清单，
   拿到后点模型输入框就能从下拉里挑。不用记名字，也不用等这里更新。
2. **从预设候选里选** —— 每个厂商带几个常见模型，切换厂商会自动填。
3. **直接手打** —— 模型名是可编辑输入框，不是只读下拉框。
   厂商刚出的模型、或者预设没覆盖到的，直接敲进去就行。

> 拉取走的是标准的 `GET /models`（OpenAI 兼容网关和 Anthropic 都支持）。
> 少数网关没实现这个接口 —— 那种情况会提示你，手填模型名即可，不影响使用。

## 工作原理

```
WPS 加载项（CEF / Chromium 104）
   ├─ 聊天侧栏         ← CreateTaskPane
   │    └─ 文档操作     ← js/doc.js，唯一持有 window.Application 的地方
   └─ 配置悬浮窗       ← ShowDialog(..., false)
              │
              │  HTTP（配置）+ SSE（对话下行）+ POST（工具结果上行）
              │  + BroadcastChannel（各页面之间）
              ▼
   本地服务（Node，零第三方依赖，默认 127.0.0.1:43130）
   ├─ 托管加载项静态文件
   ├─ 配置与凭据读写
   ├─ agent 循环：模型 ↔ 工具，最多 6 步          ← server/agent/
   │    └─ 运行时是可替换接口，以后接 DSH 只换实现
   └─ 模型适配：OpenAI 兼容 + Anthropic（含 function calling 流式）
              │
              ▼
        你选的模型厂商
```

### 三个关键设计决定

**① 请求由本地服务发出，不由加载项页面直接发。**
页面直连厂商 API 会撞 CORS（各家政策不同），Key 也会落在浏览器上下文里。
走本地服务两个问题都不存在。

**② 加载项由本地服务托管，所以是同源。**
加载项页面的 `location.origin` 就是服务地址 —— 不需要端口发现，也不需要配 CORS。

**③ 本地服务必须由外部启动。**
WPS 对加载项做了进程/COM 沙箱，实测 `CoCreateInstance('WScript.Shell')` 会报
`can not create`，加载项**无法**拉起外部进程。所以 `点我启动助手.cmd` 会注册开机自启。
